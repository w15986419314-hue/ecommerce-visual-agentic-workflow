# 飞书运营看板 ↔ EVAW 状态（一页纸）

> 运营看的是 **视觉提需进度看板**；EVAW 负责 AI 出图 / QA / 人审。  
> 两边通过同一张多维表格回写对齐：**表单提需 → EVAW 跑单 → 状态写回「看板状态」列**。

---

## 怎么用（运营）

1. 照常填 **提需表单**（字段不变）。
2. 打开同一 Base 的 **「数据表」**，新建 **看板视图**，分组字段选 **`看板状态`**。
3. 卡片会随 EVAW 进度移动：待策略 → … → 待人审 → 已批准 → 已交付。

Base：`https://scnjh6x3pkck.feishu.cn/base/B8kubs46saK9ZnsII2IcLNbXntg`

---

## 系统回写哪些列

| 列名 | 类型 | 说明 |
|------|------|------|
| **看板状态** | 单选（看板分组） | 运营可读中文进度 |
| **EVAW任务ID** | 文本 | 如 `task_8fff5a30d3` |
| **EVAW状态** | 文本 | 细粒度英文枚举（调试用） |
| **QA结果** | 文本 | Pass / Fail / PassWithRisk |
| **状态更新时间** | 文本 | 最近一次回写（本地时区） |

若表里还没有这些列，研发执行一次：

```bash
python3 -m evaw.cli feishu-kanban-sync --ensure-fields
```

（需 `FEISHU_APP_ID` / `FEISHU_APP_SECRET`，且应用对该 Base 有编辑权限。）

## EVAW 状态 → 看板状态

| EVAW `TaskStatus` | 看板状态（中文） |
|-------------------|------------------|
| Draft / ReadyForStrategy | 待策略 |
| Strategized | 策略完成 |
| KnowledgePending | 待补知识 |
| KnowledgeReady | 知识就绪 |
| Generating | 生成中 |
| GenerationFailed | 生成失败 |
| QAPending | 质检中 |
| QAFailed | 质检未过 |
| QAPassed | 质检通过 |
| QAPassedWithRisk | 质检有风险 |
| PendingReview | 待人审 |
| Approved | 已批准 |
| Rejected | 已打回 |
| Delivered | 已交付 |
| FeedbackLinked | 已反馈 |
| Cancelled | 已取消 |

## 研发 CLI

```bash
# 打印映射
python3 -m evaw.cli feishu-kanban-sync --map

# 建列（只需一次）
python3 -m evaw.cli feishu-kanban-sync --ensure-fields

# 回写一单
python3 -m evaw.cli feishu-kanban-sync --task task_8fff5a30d3

# 回写所有「表单已同步」的单
python3 -m evaw.cli feishu-kanban-sync --all --ensure-fields

# 只看将要写什么
python3 -m evaw.cli feishu-kanban-sync --task task_8fff5a30d3 --dry-run
```

自动回写时机（有 record↔task 映射时）：

- `feishu-bitable-sync` 建单成功后 → 写初始看板状态  
- `hitl-apply` 批准/打回后 → 更新看板状态  

映射来源：`artifacts/feishu_bitable_sync_state.json`（`record_id` ↔ `task_id`）。  
**只有从表单同步进来的任务** 才能写回看板行；纯 CLI 演示单没有 record_id，不会上板。
