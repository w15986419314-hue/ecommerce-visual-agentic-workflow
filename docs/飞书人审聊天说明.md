# 飞书人审（聊天批准 / 打回）— Cici 操作说明

> EVAW · HITL 聊天版 MVP  
> 目标：高风险任务停在 **PendingReview**，**不自动代审**；你在飞书看到说明后拍板。

---

## 这套怎么跑（两步）

```text
① hitl-chat-demo          ② 你拍板                    ③ 打回回流（可选）
   建任务 → 出图 → QA         回复「批准 task_xxx」         「改完再审 task_xxx」
   → PendingReview            或「打回 task_xxx 原因码」       ↓
   → 飞书发人审说明              ↓                         hitl-rework
                           hitl-apply 落库 + 通知            → 注入反馈 → gen+QA
                                                           → 再 PendingReview
```

**当前 MVP 诚实边界：** 飞书群里的「批准 / 打回」句子是给人看的操作约定；真正改状态靠 CLI `hitl-apply`（或你让助手代跑这条命令）。还没有接飞书事件订阅自动解析群消息。

---

## Cici 你怎么操作

### 1. 等人审消息出现

群里会出现类似（**含五维 QA、reason_code、候选图 uri/版本、风险说明**）：

```text
[EVAW 人审待办] task_id=task_xxxxxxxx
状态=PendingReview  sku=SKU-BED-STRUCT  platform=jd
风险说明：新品 + 结构敏感 + QA=PassWithRisk（系统不代审，需你拍板）

QA overall=PassWithRisk  reason_code=FIDELITY_STRUCTURE  primary=product_fidelity
五维 QA：
  · 产品保真(product_fidelity)=Risk — Structure angle near-miss on side rail…
  · 品牌规范(brand)=Pass — …
  · 文案准确(text)=Pass — …
  · 版式/平台(layout)=Pass — …
  · 移动端可读(mobile_readability)=Pass — …
建议修复：
  · Tighten side-rail structure ref; re-gen candidate 1

候选图（3）：
  1. version=v1  uri=stub://generated/SKU-BED-STRUCT/hero/cand_1.png
  2. version=v2  uri=stub://…
  3. version=v3  uri=stub://…
说明：stub/simulated 的 uri 是占位路径；正式版会附可点开的预览。

· 批准 → 回复：「批准 task_xxxxxxxx」
· 打回 → 回复：「打回 task_xxxxxxxx TEXT_ERROR」
```

你主要看：**风险说明**（为什么卡你）、**五维里哪一维是 Risk/Fail**、**reason_code**、**候选图列表**。然后记下 **task_id** 拍板。

### 2. 批准

在群里写：`批准 task_xxxxxxxx`（示意），然后执行：

```bash
cd ecommerce-visual-agentic-workflow
python3 -m evaw.cli hitl-apply --task task_xxxxxxxx --decision approve
```

结果：`PendingReview → Approved → Delivered`，飞书再收到结果通知。

### 3. 打回

在群里写：`打回 task_xxxxxxxx TEXT_ERROR`（示意），然后执行：

```bash
python3 -m evaw.cli hitl-apply --task task_xxxxxxxx --decision reject --reason TEXT_ERROR
```

结果：`PendingReview → Rejected`，飞书通知带 reason_code；看板「已打回」。  
常用原因码：`FIDELITY_STRUCTURE` / `TEXT_ERROR` / `BRAND_VIOLATION` / `LAYOUT_PLATFORM` / `BUSINESS_JUDGEMENT`。

### 4. 打回回流（改完再审）

打回不是终点。按原因码默认回流（见 `REASON_DEFAULT_REFLOW`）：

| reason_code | 回流到 | 含义 |
|-------------|--------|------|
| `FIDELITY_*` / `TEXT_ERROR` / `LAYOUT_*` / … | **Generating** | 保留策略，重跑出图+QA |
| `BRAND_VIOLATION` / `BUSINESS_JUDGEMENT` / `AUDIT_BRAND` | **Strategized** | 重绑知识后再出图 |

群里约定句式：`改完再审 task_xxxxxxxx`

```bash
# 等价命令（二选一）
python3 -m evaw.cli hitl-rework --task task_xxxxxxxx
python3 -m evaw.cli hitl-apply --task task_xxxxxxxx --decision rework
```

结果：打回反馈写入 strategy/brief → stub/live 重跑 gen+QA → 高风险再次 **PendingReview**（人审闸门不变），飞书 + 看板同步。  
然后再 `approve` / `reject`。

### 5. 演示整条「等人」链路（本地）

```bash
# 推到 PendingReview + 飞书说明（不代审）
python3 -m evaw.cli hitl-chat-demo

# 再人工应用决策（把 task_id 换成上一步输出）
python3 -m evaw.cli hitl-apply --task <task_id> --decision approve
# 或打回 → 改完再审 → 再人审
python3 -m evaw.cli hitl-apply --task <task_id> --decision reject --reason FIDELITY_STRUCTURE
python3 -m evaw.cli hitl-rework --task <task_id>
python3 -m evaw.cli hitl-apply --task <task_id> --decision approve
```

需真连飞书时：`.env.local` 里配置 `FEISHU_APP_ID` / `FEISHU_APP_SECRET` / `FEISHU_CHAT_ID`。  
强制本地 mock：加 `--feishu-mock`。

## 人审消息里有什么（方便看懂）

| 区块 | 你怎么用 |
|------|----------|
| **风险说明** | 一句话：新品 / 结构敏感 / PassWithRisk / 抽检… |
| **QA overall + reason_code** | 总结果与建议回流码（打回时常直接用） |
| **五维 QA** | 产品保真 · 品牌 · 文案 · 版式 · 移动端可读；看哪维是 Risk/Fail |
| **候选图** | `version` + `uri` 列表（MVP 多为 stub 占位路径） |
| **批准 / 打回 / 改完再审** | 群里约定句式 + `hitl-apply` / `hitl-rework` CLI |

实现：`evaw.hitl.format_hitl_pending_chat` · 场景 `hitl-chat-demo`。

## 和「localhost 审批页」的关系

| | 说明 |
|---|---|
| **旧 feishu-demo** | 会走到 PendingReview，但脚本会 **自动 Lead Approve**（演示闭环） |
| **本 hitl-chat-demo** | **停在 PendingReview**，等人用聊天约定 + `hitl-apply` |
| **localhost 链接** | 仍是占位控制台，手机打不开；聊天人审就是为了绕开它 |

任务快照落在 `artifacts/hitl_pending/<task_id>.json`（已 gitignore）。

## 你（视觉 Lead）在证明什么

- AI 跑流程与初筛；**高风险必须你拍板**。  
- 打回要带 **reason_code**，方便回流与复盘。  
- **打回 → 改完再审** 是产品闭环：系统注入反馈重跑，人审闸门不变。  
- 可讲清：「闸门是产品设计，不是脚本替我点通过。」
