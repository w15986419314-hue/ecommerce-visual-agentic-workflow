# 飞书人审（聊天批准 / 打回）— Cici 操作说明

> EVAW · HITL 聊天版 MVP  
> 目标：高风险任务停在 **PendingReview**，**不自动代审**；你在飞书看到说明后拍板。

---

## 这套怎么跑（两步）

```text
① hitl-chat-demo          ② 你拍板
   建任务 → 出图 → QA         回复「批准 task_xxx」
   → PendingReview            或「打回 task_xxx 原因码」
   → 飞书发人审说明              ↓
                           hitl-apply 落库 + 再通知飞书
```

**当前 MVP 诚实边界：** 飞书群里的「批准 / 打回」句子是给人看的操作约定；真正改状态靠 CLI `hitl-apply`（或你让助手代跑这条命令）。还没有接飞书事件订阅自动解析群消息。

## Cici 你怎么操作

### 1. 等人审消息出现

群里会出现类似：

```text
[EVAW 人审待办] task_id=task_xxxxxxxx
状态=PendingReview  sku=SKU-BED-STRUCT  QA=PassWithRisk
…
· 批准 → 回复：「批准 task_xxxxxxxx」
· 打回 → 回复：「打回 task_xxxxxxxx TEXT_ERROR」
```

记下 **task_id**。

### 2. 批准

在群里写：`批准 task_xxxxxxxx`（示意），然后执行：

```bash
cd ecommerce-visual-agentic-workflow
python3 -m evaw.cli hitl-apply --task task_xxxxxxxx --decision approve
```

结果：`PendingReview → Approved → Delivered`，飞书再收到结果通知。

### 3. 打回

在群里写：`打回 task_xxxxxxxx TEXT_ERROR`（示意），然后执行：

```bash
python3 -m evaw.cli hitl-apply --task task_xxxxxxxx --decision reject --reason TEXT_ERROR
```

结果：`PendingReview → Rejected`，飞书通知带 reason_code。  
常用原因码：`FIDELITY_STRUCTURE` / `TEXT_ERROR` / `BRAND_VIOLATION` / `LAYOUT_PLATFORM` / `BUSINESS_JUDGEMENT`。

### 4. 演示整条「等人」链路（本地）

```bash
# 推到 PendingReview + 飞书说明（不代审）
python3 -m evaw.cli hitl-chat-demo

# 再人工应用决策（把 task_id 换成上一步输出）
python3 -m evaw.cli hitl-apply --task <task_id> --decision approve
# 或
python3 -m evaw.cli hitl-apply --task <task_id> --decision reject --reason FIDELITY_STRUCTURE
```

需真连飞书时：`.env.local` 里配置 `FEISHU_APP_ID` / `FEISHU_APP_SECRET` / `FEISHU_CHAT_ID`。  
强制本地 mock：加 `--feishu-mock`。

## 和「localhost 审批页」的关系

| | 说明 |
|---|---|
| **旧 feishu-demo** | 会走到 PendingReview，但脚本会 **自动 Lead Approve**（演示闭环） |
| **本 hitl-chat-demo** | **停在 PendingReview**，等人用聊天约定 + `hitl-apply` |
| **localhost 链接** | 仍是占位控制台，手机打不开；聊天人审就是为了绕开它 |

任务快照落在 `artifacts/hitl_pending/<task_id>.json`（已 gitignore）。
